# Публикация через public_html

**Адрес: https://se.ifmo.ru/~s504568/lab2/**

Сделано по принципу из [инструкции AppLoidx](https://github.com/AppLoidx/Web-Development-Cheats/blob/master/itmo-university/deploy.md):
публичный вход находится в `~/public_html/lab2`. Каталоги имеют права 755,
файлы — 644. Права домашнего каталога не расширялись.

## Как проходит запрос

```text
Браузер → https://se.ifmo.ru/~s504568/lab2/
  → общий веб-сервер → ~/public_html/lab2/index.php
  → свой Apache на Helios:127.0.0.1:24000
  → Java FastCGI на Helios:35481 (только для api/check)
```

Свой Apache отдаёт HTML, CSS и JS из `~/web/lab2/public` и направляет
POST /api/check к Java. PHP используется только как шлюз к собственному Apache:
он не считает попадание и не изменяет координаты. В общем Apache модуль proxy
не включён, поэтому одного RewriteRule с проксированием недостаточно.
Инструкция public_html описывает статическую публикацию; шлюз добавлен для Java.

## Файлы

- `~/web/lab2/` — основное приложение, jar, конфигурация и скрипты.
- `~/public_html/lab2/index.php` — шлюз на фиксированный внутренний адрес Apache.
- `~/public_html/lab2/.htaccess` — маршрутизация публичных URL в шлюз.

Разрешены только главная страница, index.html, style.css, script.js и api/check.
Произвольные файлы, исходники и внешние адреса через шлюз недоступны.
Сохраняются тело POST, Content-Type, строка запроса и HTTP-статус ответа.
Числа передаются целиком. Шлюз не ограничивает число цифр.
При недоступной Java/Apache публичный API возвращает JSON с нашим сообщением.

## Обновление и запуск

В комплект helios-upload входят public_html и publish.sh.
Перенеси его содержимое в `~/web/lab2` и выполни:

```sh
sh /home/studs/s504568/web/lab2/server.sh
```

Скрипт запускает Java с `-Xms16m -Xmx128m`, Apache и publish.sh.
Последний создаёт public_html/lab2 и копирует туда шлюз и .htaccess.
Отдельная повторная публикация: `sh /home/studs/s504568/web/lab2/publish.sh`.

Остановка и восстановление Java описаны в [WinSCP.md](WinSCP.md).
SSH-туннель и локальный адрес 127.0.0.1:8081 для публичного сайта не используются.
Если остановить Java, проверка покажет ошибку; сама страница останется доступной.
