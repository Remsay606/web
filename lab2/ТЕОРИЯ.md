Этот файл объясняет код, который лежит рядом: от разметки страницы до получения

## 1. Что программа делает целиком

Представь два отдельных участника. Браузер умеет показать форму, нарисовать
график и отправить запрос. Java умеет проверить числа и решить, попала ли точка
в область. Посредник Apache получает HTTP-запрос от браузера и передаёт его Java.

Последовательность одной проверки:

1. Пользователь выбирает X и R, вводит Y.
2. JavaScript перехватывает отправку формы и проверяет ввод.
3. `fetch` отправляет POST на `api/check` без перезагрузки страницы.
4. Apache передаёт метод, заголовки и тело запроса Java по FastCGI.
5. Java заново проверяет всё и вычисляет попадание.
6. Java возвращает JSON с координатами, результатом и временем.
7. JavaScript получает JSON, добавляет строку в таблицу и точку на график.
8. История сохраняется в localStorage, чтобы пережить перезагрузку страницы.

Это AJAX: обмен данными с сервером в фоне с обновлением части страницы.
Буква X исторически означала XML, но AJAX спокойно работает с JSON.

### Зачем здесь два сервера

Apache отдаёт готовые файлы: HTML, CSS, JavaScript. Такой контент называют
статическим: серверу не нужно вычислять его заново для каждой точки.
Java создаёт ответ в зависимости от x, y, r. Это динамический контент.
FastCGI связывает веб-сервер с уже работающим приложением.

В обычном CGI сервер может запускать отдельный процесс на каждый запрос.
В FastCGI Java запускается один раз, затем многократно принимает запросы в цикле.
Сами сообщения между Apache и Java имеют двоичный формат FastCGI, а не формат HTTP.
Поэтому открыть FastCGI-порт в браузере как обычную страницу нельзя.

### Какие файлы за что отвечают

| Файл | Роль |
|---|---|
| `public/index.html` | Элементы страницы и поля формы |
| `public/style.css` | Цвета, размеры, расположение |
| `public/script.js` | Форма, AJAX, таблица, история, рисунок |
| `src/AreaChecker.java` | Проверка принадлежности трём фигурам |
| `src/RequestHandler.java` | Валидация протокола и чисел, создание JSON |
| `src/Main.java` | Приём FastCGI и отправка ответа |
| `lib/fastcgi-lib.jar` | Готовая библиотека FastCGI из задания |
| `config/httpd.conf` | Правила работы Apache на Helios |
| `tools/` | Сборка и локальный запуск на Windows |
| `tests/` | Проверки корректности и обработки ошибок |

На Helios Node.js и папка tools для обслуживания сайта не используются.
Основное приложение — три Java-класса и три файла страницы, без фреймворков.

## 2. Математика: понять до чтения Java

В первой четверти x и y положительные, во второй x отрицательный, y положительный,
в третьей оба отрицательные, в четвёртой x положительный, y отрицательный.
В нашем варианте в третьей четверти закрашенной фигуры нет.

### Круг справа сверху

Полный круг с центром в начале координат задаётся `x² + y² <= R²`.
Мы дополнительно требуем `x >= 0` и `y >= 0`, чтобы оставить только первую четверть.
Корень извлекать не нужно: сравниваем квадраты.

Пример при R = 2: (1, 1) попадает, потому что 1 + 1 <= 4.
(2, 1) не попадает, потому что 4 + 1 > 4.
(2, 0) лежит на границе и попадает.

### Треугольник слева сверху

Вершины: (0, 0), (−R/2, 0), (0, R/2).
Наклонная сторона соединяет последние две вершины. Её уравнение `y = x + R/2`.
Внутри треугольника y не больше этой прямой: `y - x <= R/2`.
Дополнительно нужны `x <= 0` и `y >= 0`.

Отдельная проверка `x >= -R/2` не обязательна: из `y >= 0` и `y - x <= R/2`
это уже следует. Если x слишком отрицательный, последнее неравенство не выполнится.

Пример при R = 3: (−1, 0.5) лежит на наклонной стороне и попадает.
(−1, 0.6) находится выше неё и не попадает.

### Прямоугольник справа снизу

Левая сторона x = 0, правая x = R/2, нижняя y = −R, верхняя y = 0.
Поэтому проверяем `0 <= x <= R/2` и `-R <= y <= 0`.
При R = 2 точка (1, −1.5) попадает, (2, −1.5) — нет.

### Объединение фигур и границы

Результат — `circle || triangle || rectangle`. Оператор `||` означает «или»:
достаточно попадания хотя бы в одну фигуру. Оператор `&&` означает «и»:
все условия для одной фигуры должны выполниться одновременно.
Знаки `<=` и `>=` включают границы. Точка (0, 0) попадает.

Интервал допустимого ввода Y — отдельное правило: **−3 < Y < 3**.
Например, при R = 3 точка (0, 3) геометрически принадлежит кругу,
но форма и сервер её отклонят, потому что Y = 3 запрещён заданием.
Нельзя путать границу фигуры с границей допустимого ввода.

## 3. HTML: устройство `public/index.html`

### Начало документа

`<!DOCTYPE html>` включает современный режим HTML.
`<html lang="ru">` задаёт русский язык: это помогает браузеру и программам озвучивания.
В `<head>` находятся настройки документа, в `<body>` — видимое содержимое.
`<meta charset="UTF-8">` позволяет корректно показывать русский текст.
`viewport` подстраивает ширину страницы под экран телефона.
`<title>` — название вкладки браузера.

`<link rel="stylesheet" href="style.css">` подключает отдельный CSS-файл.
`<script src="script.js" defer>` подключает JavaScript. `defer` позволяет
загрузить скрипт параллельно с HTML, но выполнить после разбора разметки.
Поэтому `document.getElementById(...)` уже найдёт элементы.

### Header, main, section

`header` содержит ФИО, группу и вариант. `main` — основную часть страницы.
Каждая `section` объединяет связанный блок: график, форму или результаты.
`h1` — главный заголовок, `h2` — заголовки блоков.
Это смысловые теги: они объясняют структуру, а внешний вид задаёт CSS.

`id` — уникальное имя элемента, например `id="form"`.
JavaScript ищет элементы по id, CSS может обращаться к ним через `#form`.
`class="block"` повторяется у нескольких элементов: общий класс даёт им общий стиль.

`aria-labelledby="graph-title"` связывает секцию с заголовком.
Атрибуты `aria-*` помогают вспомогательным технологиям понимать интерфейс.

### Canvas

`canvas` — прямоугольный холст для рисунка JavaScript.
`width="400" height="400"` задают внутреннее разрешение в 400 на 400 точек.
CSS может уменьшить его на узком экране; математические координаты рисунка
при этом остаются в диапазоне 0…400.
Сам HTML не рисует фигуру: это делает `drawPlane` через контекст Canvas 2D.
`role="img"` и `aria-label` добавляют текстовое описание области.

### Форма и поля

`<form id="form" action="api/check" method="post" novalidate>`:

- `action` — адрес обработки относительно страницы;
- `method="post"` — отправка данных в теле HTTP-запроса;
- `novalidate` — отключение стандартных всплывающих подсказок браузера,
  потому что ошибки собирает и показывает наш JavaScript.

Серверную валидацию `novalidate` никак не отключает.
Адрес `api/check` работает с локальным сервером и с настроенным Apache.
Для публикации в другой подпапке потребуется соответствующая настройка маршрута Apache.

`label for="y"` указывает на поле с `id="y"`: щелчок по подписи активирует поле.
`name="y"` — имя параметра формы, `id="y"` — имя элемента для DOM.
Это разные задачи, хотя значения у них совпадают.

X и R — `select`, то есть выпадающие списки. Каждый `option` — один вариант.
Если у `option` нет отдельного `value`, отправляемым значением будет его текст.
Первая пустая опция заставляет явно выбрать значение.

Y — `input type="text"`: формат контролируем сами, в том числе запятую
и длинную дробь. `inputmode="decimal"` предлагает подходящую экранную клавиатуру.
Это подсказка, а не проверка. Атрибута maxlength нет: количество цифр не ограничено
кодом страницы. Проверяются формат десятичной записи и допустимый интервал Y.
`autocomplete="off"` просит браузер не подставлять старые значения.
`placeholder` — пример, а не фактическое значение поля.

Кнопка `type="submit"` отправляет форму. Событие submit также вызывается при Enter.
Кнопка очистки имеет `type="button"`, чтобы не запускать отправку.
`noscript` показывает пояснение, если JavaScript выключен.

### Сообщения и таблица

`#error` с `role="alert"` содержит ошибки. `#status` сообщает о ходе запроса
и результате; `aria-live="polite"` позволяет озвучить обновление без резкого прерывания.
`#storage-warning` отдельно сообщает о проблемах сохранения истории.

`table` — таблица; `thead` — заголовки; `tbody` — строки данных;
`tr` — строка; `th` — заголовочная ячейка; `td` — обычная.
`scope="col"` означает, что заголовок относится к столбцу.
`caption` описывает таблицу. Его визуально скрываем специальным классом,
но сохраняем доступность для программ чтения с экрана.
Строки результатов создаёт JavaScript, а не Java: серверу разрешено отвечать JSON.

## 4. CSS: полный разбор `public/style.css`

CSS-правило состоит из селектора и объявлений: `селектор { свойство: значение; }`.
Например, `body { margin: 0; }` убирает стандартный отступ у всей страницы.

### Виды селекторов, использованные в работе

| Пример | Что выбирает |
|---|---|
| `body`, `h2` | Элементы по имени тега |
| `#header` | Один элемент по id |
| `.block` | Все элементы с классом block |
| `#header > p` | Только непосредственные дочерние p внутри header |
| `#table td` | Все td внутри table на любой глубине |
| `input, select, button` | Три группы элементов одним правилом |
| `input[type="text"]` | Input с конкретным атрибутом type |
| `td[data-hit="yes"]` | Ячейка с нашим атрибутом результата |
| `button:hover` | Кнопка под указателем |
| `button:disabled` | Отключённая кнопка |
| `:focus-visible` | Элемент с видимым фокусом, обычно при работе с клавиатуры |
| `#error:empty` | Пустой элемент error |
| `#header > h1::first-letter` | Первая буква заголовка |
| `#header > p::before` | Добавляемое оформление перед абзацем |

Псевдокласс описывает состояние элемента, например `:hover`.
Псевдоэлемент выделяет часть элемента или создаёт оформительскую вставку,
например `::first-letter` и `::before`.

### Основа и шапка

`font: 16px Arial, sans-serif` задаёт размер и семейство шрифта.
`sans-serif` — запасное семейство, если Arial недоступен.
`color` — цвет текста, `background` — фон.
`padding` — внутренний отступ, `margin` — внешний.
Два значения `padding: 20px 12px` означают сверху/снизу 20, слева/справа 12.

У шапки оставлен `font-family: fantasy`, как в первой лабораторной.
`text-align: center` центрирует текст, а не сам блок.
`::first-letter` красит первую букву; `::before { content: "• "; }`
добавляет декоративную точку перед подписью.

### Основная колонка и блоки

`max-width: 800px` ограничивает максимальную ширину, но разрешает сжиматься.
`margin: 0 auto` центрирует блок по горизонтали.
`border` задаёт рамку, `border-radius` скругляет углы.
У canvas `display: block` убирает поведение строчного элемента,
`max-width: 100%` не даёт выйти за ширину родителя, `height: auto` сохраняет пропорции.

### Поля, подписи и кнопки

`display: block` переносит подпись на собственную строку.
`font-weight: bold` делает подпись жирной.
`font: inherit` у полей и кнопок наследует шрифт страницы.
Без него браузер мог бы использовать отдельный мелкий системный шрифт.

`width: 100%` растягивает поле на ширину блока.
`box-sizing: border-box` включает рамку и padding в эту ширину.
Иначе поле шириной 100% плюс рамки и отступы могло бы выйти за контейнер.
`padding: 2% 3%` задаёт внутренние отступы в процентах от ширины содержащего блока.
`::placeholder` меняет цвет примера ввода.

У кнопок `cursor: pointer` показывает указатель руки.
`:hover` немного затемняет кнопку через `filter: brightness(0.9)`.
При `:disabled` кнопка полупрозрачная, курсор становится `wait`.
Сам запрет нажатия создаёт HTML-свойство `disabled`, CSS лишь показывает состояние.
`:focus-visible` добавляет заметную обводку для работы клавишей Tab.
`[aria-invalid="true"]` окрашивает рамку ошибочного поля.

### Сообщения и таблица

`white-space: pre-line` сохраняет переносы строк из текста ошибок.
Поэтому несколько сообщений, соединённых через `\n`, отображаются столбиком.
`overflow-wrap: anywhere` позволяет переносить длинную дробь и другой длинный текст.
`:empty { display: none; }` скрывает пустое место сообщения.

`.section-heading` использует Flexbox: заголовок и кнопка располагаются в ряд.
`justify-content: space-between` раздвигает их к краям,
`align-items: center` выравнивает по вертикали, `gap` задаёт промежуток.
`flex-wrap: wrap` разрешает перенос, если места мало.

У таблицы `border-collapse: collapse` объединяет соседние рамки.
`table-layout: fixed` задаёт устойчивую ширину столбцов; столбцу Y отведено 33%.
`min-width: 700px` не даёт длинной дроби сжать подписи результата и времени
до одной буквы в строке. На узком экране таблица прокручивается горизонтально.
Селектор `#table > thead th` оформляет заголовки столбцов.
Атрибут `data-hit` устанавливает JavaScript; по нему CSS красит результат.
`.table-scroll { overflow-x: auto; }` разрешает прокрутить таблицу на узком экране,
сохраняя все столбцы.

### Скрытый caption и маленький экран

`.visually-hidden` делает элемент размером 1×1 пиксель, обрезает его и выводит
из обычного потока. Описание остаётся в дереве доступности.
`@media (max-width: 480px)` применяет правила только к узким экранам:
уменьшаются поля блоков, размер заголовка и отступы ячеек.

### Каскад и специфичность

Несколько CSS-правил могут подходить одному элементу. При обычных условиях
селектор с id имеет больший приоритет, чем селектор с классом,
а класс — больший, чем имя тега. При одинаковой специфичности выигрывает
правило ниже в файле. Свойства вроде font могут наследоваться от родителя.
В работе нет `!important`, поэтому оформление легче проследить.

## 5. JavaScript: основные конструкции

Java и JavaScript — разные языки. Java здесь выполняется на сервере,
JavaScript — в браузере. У них похожие скобки и часть операторов,
но разные среды, типы и стандартные библиотеки.

`'use strict'` включает строгий режим: например, случайное присваивание
необъявленной переменной вызовет ошибку.
`const` создаёт переменную, которой нельзя назначить другое значение.
Объект или массив внутри const всё равно может изменяться.
`let` используется, когда значение переменной заменяется: `results`, `pending`.

Массив — упорядоченный список, например `['1', '1.5', '2']`.
Объект — набор полей: `{ x: '1', y: '-1.5', hit: true }`.
`===` сравнивает без автоматического преобразования типов.
`!` означает отрицание, `&&` — и, `||` — или.
`условие ? значение1 : значение2` — короткая условная запись.

DOM — представление HTML как дерева объектов. `document.getElementById('y')`
возвращает объект поля. `.value` содержит ввод, `.textContent` — текст,
`.disabled` включает или отключает элемент управления.
`addEventListener` регистрирует функцию, которую браузер вызовет при событии.

## 6. `public/script.js`: константы и функции по порядку

### Списки и ссылки на элементы

`X_VALUES`, `R_VALUES` повторяют допустимые значения варианта.
Они нужны для проверки: один select не защищает от изменения HTML в инструментах разработчика.
`STORAGE_KEY` — отдельное имя истории этой работы.
`MAX_RESULTS = 500` ограничивает расход памяти и время перерисовки.

Переменные `form`, `xSelect`, `yInput`, `rSelect`, `errorBox`, `statusBox`,
`storageWarning`, `submitButton`, `clearButton`, `tableBody`, `canvas`
хранят ссылки на одноимённые части интерфейса.
Так не приходится искать их заново перед каждым действием.

`ctx = canvas.getContext('2d')` — инструмент для рисования.
`CENTER = 200` — центр холста 400×400, `UNIT = 140` — базовый отступ крайних
делений от центра в пикселях. Размер R на рисунке зависит от автоматического масштаба.
`Intl.DateTimeFormat('ru-RU', ...)` создаёт форматировщик даты,
использующий часовой пояс браузера.
`pending` показывает, есть ли незавершённый запрос.

### normalizeY(value)

`replace(/^ +| +$/g, '')` удаляет обычные пробелы в начале и конце.
`replace(',', '.')` превращает десятичную запятую в точку.
Внутренние пробелы и управляющие символы не удаляем: это неверный ввод.
Используется именно такая нормализация и в Java, чтобы обе проверки совпадали.
Если запятых две, после первой замены одна останется и проверка отклонит строку.

### checkY(value)

Функция возвращает пустую строку при успехе или текст ошибки при неудаче.
Пустой ввод проверяется отдельно, чтобы дать понятное сообщение.
Для проверки временно нормализуем запись через normalizeY, затем проверяем
переносы строк и десятичный формат. Длина числа не ограничивается.

Регулярное выражение `[+-]?(?:[0-9]+(?:\.[0-9]*)?|\.[0-9]+)` означает:

- `[+-]?` — необязательный знак;
- `[0-9]+` — одна или больше цифр;
- `\.` — именно точка, а не любой символ;
- часть после неё может быть пустой, поэтому `1.` допустимо;
- альтернатива после `|` разрешает `.5`, но требует цифры после точки;
- `^` и `$` ограничивают строку целиком; переносы отдельно запрещены,
  потому что в JavaScript `$` способен совпасть и перед завершающим переносом.

Для проверки интервала не используем `Number(y)`: длинное `2.999...`
могло бы округлиться до 3. Здесь достаточно проверить целую часть модуля числа.
Убираем начальный знак, берём часть до точки и удаляем ведущие нули.
Если целая часть оказалась пустой, используем строку `'0'`.

Для любого десятичного числа с целой частью 0, 1 или 2 его модуль меньше 3,
сколько бы цифр ни было в дробной части. Целая часть 3 и больше уже не подходит.
Поэтому `whole.length > 1 || whole > '2'` точно обнаруживает выход из интервала:
сначала проверяется число разрядов, затем сравниваются однозначные цифры как строки.
Знак значения не важен, потому что интервал симметричный: −3 < Y < 3.
Например, `-0002.999...` допустимо, а `3.000...` — нет.
Дробь не преобразуется в приближённый Number или гигантскую степень BigInt.
Количество цифр не влияет на точность; ограничением остаются ресурсы компьютера.

### isResult(item)

Проверяет структуру результата перед добавлением в таблицу или загрузкой истории.
Сначала исключает null и не-объекты. Потом проверяет x и r по спискам,
y через checkY, hit как настоящий boolean, время как разбираемую дату,
elapsedMicros как неотрицательное безопасное целое число.

`typeof` узнаёт тип, `includes` проверяет наличие в массиве,
`Number.isFinite` исключает NaN и бесконечность.
`Number.isSafeInteger` проверяет целое число в диапазоне точного представления Number.
Эта функция проверяет формат, а не криптографическую подлинность истории:
человек, контролирующий свой браузер, может подменить корректно оформленную запись.
Пересчитывать попадание по введённым координатам должен сервер.

### loadResults()

В try читаем строку из localStorage. Если ключ отсутствует, получаем null
и возвращаем пустой массив. Искусственного ограничения длины строки истории нет:
одна корректная длинная дробь не должна исчезнуть после перезагрузки.
`JSON.parse` превращает строку в значение JavaScript.
`Array.isArray` проверяет, что это именно массив.

`slice(-MAX_RESULTS)` берёт последние 500 записей, `filter(isResult)` оставляет
валидные. При пропуске записей показываем предупреждение.
`catch` обрабатывает повреждённый JSON и запрет доступа к localStorage:
работа страницы продолжается с пустой историей.

### saveResults()

`JSON.stringify(results)` превращает массив в JSON-строку.
`localStorage.setItem` сохраняет её под нашим ключом.
Операция может завершиться ошибкой из-за настроек браузера или квоты.
Поэтому она находится в try/catch: ошибка хранения не отменяет успешный ответ Java.
Пользователь увидит, что после перезагрузки история может исчезнуть.

### renderTable()

`replaceChildren()` убирает старые строки. Если результатов нет, создаётся
одна ячейка с `colSpan = 6`: она занимает всю ширину таблицы.
`[...results]` создаёт копию массива, `.reverse()` разворачивает копию.
Новые результаты идут сверху, но порядок исходной истории не меняется.

`insertRow()` создаёт строку, `insertCell()` — ячейку.
Мы присваиваем `.textContent`, поэтому текст не интерпретируется как HTML.
Это препятствует внедрению разметки и скриптов через данные таблицы.
`row.cells[3].dataset.hit` создаёт атрибут `data-hit` для CSS-окрашивания.
Время из UTC-строки превращается в Date и форматируется для пользователя.

### drawPlane(): фигура и оси

Если ctx отсутствует, выходим: таблица и запросы могут работать даже без Canvas 2D.
`clearRect` стирает прежний рисунок. `fillStyle` задаёт цвет заливки,
`beginPath` начинает новый контур.

Круг: `moveTo` переходит в центр, `arc` рисует дугу радиуса UNIT
от −π/2 до 0. На холсте ось y направлена вниз, поэтому это верхняя правая четверть.
`closePath` замыкает контур обратно к началу, создавая сектор.
Треугольник задаётся тремя вершинами через `moveTo` и `lineTo`.
Прямоугольник `rect(CENTER, CENTER, UNIT / 2, UNIT)` имеет ширину R/2
и высоту R вниз. `fill()` закрашивает все три контура.

`strokeStyle`, `lineWidth` и `stroke()` отвечают за линии осей и стрелки.
`fillText` пишет подписи, `fillRect` делает короткие деления на осях.
Цикл по `[1, 0.5, -0.5, -1]` располагает метки R, R/2, −R/2, −R.
Деструктуризация `[k, label]` извлекает коэффициент и его подпись из пары.

### drawPlane(): точки и масштаб

При отсутствии выбранного R рисунок области остаётся схематическим,
а точки пока не показываются. После выбора берём только результаты с этим R.
Для каждой точки математические координаты преобразуются в пиксели:

```text
scale = UNIT / extent
px = CENTER + x * scale
py = CENTER - y * scale
```

extent — максимум между R и округлёнными вверх модулями координат всех
результатов выбранного R. Например, при x = 5 и R = 1 extent равен 5:
точка рисуется на 140 пикселей правее центра, а радиус области равен 28 пикселям.
areaSize = R * scale задаёт размер области. Все три фигуры и точки используют
один масштаб, поэтому их взаимное расположение сохраняется.
Минус в py нужен потому, что экранная ось y направлена вниз.
Для рисунка достаточно Number: точный ответ уже вычислен в Java,
а холст всё равно показывает конечное число пикселей.

Все точки выбранного R помещаются на холсте. Каждая рисуется кружком радиуса
4 пикселя нужного цвета. Если extent равен R, деления подписываются R и R/2;
при расширенном масштабе показываются численные координаты делений.
Подпись поясняет текущий R, цвета и диапазон осей.
История с другим R не смешивается с текущим рисунком.

## 7. Отправка формы: самый важный обработчик JavaScript

`let results = loadResults()` загружает историю до первоначальной отрисовки.
`form.addEventListener('submit', async event => { ... })` регистрирует
асинхронный обработчик отправки. `event.preventDefault()` отменяет обычный
переход браузера на страницу ответа формы.

Если `pending` уже true, второй запрос не создаём. Считываем x, y, r;
проверяем списки и Y. Для каждого поля устанавливаем `aria-invalid`.
Ошибки собираются массивом, пустые отбрасываются через `filter(Boolean)`,
остальные соединяются `join('\n')`. При любой ошибке выходим до запроса.

### Блокировка и таймаут

Перед запросом `pending = true`, обе кнопки временно disabled.
Сообщение «Проверяем…» даёт понять, что действие началось.
`AbortController` создаёт возможность прервать fetch.
`setTimeout(..., 12000)` вызывает abort через 12 секунд.
Это ограничивает ожидание в браузере, но не отменяет уже сделанное вычисление
на удалённом сервере; нельзя считать abort откатом серверной операции.

### fetch и тело запроса

```javascript
fetch(form.action, {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded;charset=UTF-8' },
    body: new URLSearchParams({ x, y, r }),
    signal: controller.signal,
    cache: 'no-store'
});
```

`form.action` — полный адрес обработки, вычисленный браузером из HTML.
`URLSearchParams` корректно кодирует параметры: плюс в числе становится `%2B`,
а не ошибочно превращается в пробел. Тело выглядит примерно `x=1&y=-1.5&r=2`.
Заголовок Content-Type объясняет серверу формат тела.
`signal` подключает отмену, `cache: 'no-store'` запрещает использовать кэш.

`await` ждёт завершения Promise, не блокируя весь интерфейс браузера.
Promise — объект будущего результата операции.
Асинхронная функция приостанавливает своё выполнение до ответа,
а браузер в это время продолжает обрабатывать другие события.

### Проверка ответа

Сначала убеждаемся, что Content-Type содержит application/json.
Иначе, например, HTML-страница ошибки Apache не попадёт в `response.json()`
как будто это правильный результат. Показываем понятное сообщение с HTTP-статусом.
`?.` — необязательная цепочка: если заголовка нет, не вызываем метод у null.

`response.json()` разбирает JSON. `response.ok` истинен для статусов 200…299.
Важно: fetch сам по себе обычно не бросает исключение при HTTP 400 или 500.
Статус нужно проверить отдельно. `throw new Error(...)` передаёт ошибку в catch.

Успешный ответ проходит isResult; дополнительно сверяем x и r с отправленными.
Y сервер возвращает с исходными цифрами и разделителем, без обрезания конечных нулей.
Далее `push` добавляет результат, `slice(-500)` оставляет последние записи,
saveResults сохраняет, renderTable обновляет таблицу, drawPlane — график.
Локального вычисления попадания в этом обработчике нет.

### catch и finally

В catch различаем отмену по таймауту, сетевую TypeError и остальные ошибки.
Для HTTP-ошибки показываем сообщение сервера, но через textContent.
Старые результаты остаются: неуспешная проверка не очищает историю.

finally выполняется и при успехе, и при исключении.
В нём снимаем таймер, сбрасываем pending и включаем кнопки.
Без finally одна ошибка сети могла бы навсегда оставить кнопку disabled.

### Остальные события

Очистка: заменяет results пустым массивом, сохраняет его,
обновляет таблицу и график и сообщает об очистке.
`localStorage.clear()` не используется, чтобы не стирать другие данные сайта.
Смена R вызывает только drawPlane: не отправляет повторные запросы.

Событие `storage` приходит, когда другое окно того же origin изменило хранилище.
Перечитываем нашу историю и обновляем отображение.
Это синхронизация отображения, а не полноценная многопользовательская база:
одновременные записи разных вкладок могут перезаписать друг друга.
В конце файла вызываются renderTable и drawPlane для первого отображения страницы.

## 8. Java: основы синтаксиса для этой работы

`import` подключает имена классов из библиотек.
`public class` объявляет класс, доступный другим классам.
`final class` запрещает наследование от него: здесь наследование не требуется.
`static` позволяет вызвать метод у класса без создания объекта.
`private` скрывает член класса от внешнего кода.
Пустой private-конструктор у AreaChecker и RequestHandler запрещает создавать
бессмысленные экземпляры: эти классы содержат только статические функции.

`String` — строка, `int` — 32-битное целое, `long` — 64-битное,
`boolean` — true или false. `byte[]` — массив байтов.
`new` создаёт объект. `return` завершает метод и возвращает результат.
`if` выбирает ветку, `while (true)` повторяется без заранее заданного конца.

Исключение — сообщение о сбое, которое меняет обычный порядок исполнения.
`try/catch` позволяет обработать сбой, `throw` — создать его,
`throws IOException` в объявлении метода предупреждает вызывающий код,
что ошибка ввода-вывода может выйти наружу.

## 9. `src/AreaChecker.java`: точная геометрия

`contains(BigDecimal x, BigDecimal y, BigDecimal r)` принимает уже проверенные числа.
Здесь нет HTTP, чтения формы или таблицы — только три математических условия.
Проверкой допустимых диапазонов занимается RequestHandler.

### Почему BigDecimal

`double` хранит приближённые двоичные дроби. Некоторые десятичные числа,
например 0.1, не представляются в нём точно. Число чуть ниже 3 может округлиться
до 3, а точка около дуги получить неверный ответ.
`new BigDecimal(строка)` точно хранит десятичный ввод произвольной точности
в пределах возможностей Java и доступной памяти. Лимит цифр в приложении не задан.
Не используем `new BigDecimal(double)`, чтобы не занести погрешность до вычисления.

Основные операции:

| Java | Смысл |
|---|---|
| `a.add(b)` | a + b |
| `a.subtract(b)` | a − b |
| `a.multiply(b)` | a × b |
| `a.divide(b)` | a / b |
| `a.negate()` | −a |
| `a.signum()` | −1, 0 или 1 по знаку |
| `a.compareTo(b)` | Отрицательное число, 0 или положительное число |

Для BigDecimal нельзя написать `a <= b`.
Запись `a.compareTo(b) <= 0` означает «a не больше b».
`compareTo` сравнивает численное значение, поэтому 1.0 и 1.00 равны.
`equals` у BigDecimal учитывает ещё и масштаб, поэтому для геометрии его не используем.
Объекты BigDecimal неизменяемые: операции возвращают новый результат.

`half = r.divide(BigDecimal.valueOf(2))` вычисляет R/2.
Деление на 2 для наших конечных десятичных R всегда конечное,
поэтому правила округления не нужны.
Умножение и сложение здесь тоже без MathContext, значит без искусственного округления.

`circle`, `triangle`, `rectangle` — именованные boolean-переменные,
каждая повторяет соответствующие неравенства из раздела 2.
Итог возвращается через логическое или. Короткое замыкание `&&` позволяет
не считать квадрат, если знак координаты уже исключил нужную четверть.

## 10. `src/RequestHandler.java`: разбор запроса по шагам

### Импорты и константы

InputStream читает тело запроса; IOException описывает ошибки чтения.
URLDecoder разбирает percent-кодирование формы; StandardCharsets задаёт кодировку.
Instant даёт текущее время UTC. Map/HashMap хранят пары имя-значение,
Set — набор допустимых значений, Properties — параметры FastCGI.
BigInteger нужен для точного сравнения заявленной и фактической длины запроса.
Списки X и R соответствуют HTML; ограничения размера тела в приложении нет.
THREE хранит границу Y как точное десятичное число.

`record Response(int status, String json)` — компактный контейнер двух полей.
Java сама создаёт конструктор и методы доступа `status()` и `json()`.
Это способ вернуть статус и тело одним объектом; здесь не нужен изменяемый класс.

### handle(params, input): метод и заголовки

В начале `System.nanoTime()` запоминает момент начала обработки.
Эти монотонные часы подходят для длительности: перевод системных часов
не сделает прошедшее время отрицательным.

REQUEST_METHOD должен быть POST. При другом методе возвращаем 405.
QUERY_STRING должен быть пустым: форма передаёт параметры только в теле.
Это исключает неоднозначность вроде x=1 в адресе и x=2 в теле.

CONTENT_TYPE берём до точки с запятой. Так принимается и обычный тип,
и тип с `;charset=UTF-8`. Сравниваем без учёта регистра.
Другой формат, например application/json, даёт 415.

CONTENT_LENGTH должен содержать одну или больше цифр. Это строковая запись
длины тела в байтах. Формат проверяется независимо от количества разрядов.
Число разбирается как BigInteger, чтобы переполнение обычного int или long
не нарушило проверку длины.

### Чтение тела

Явный цикл `input.read(buffer)` читает тело блоками по 8192 байта без обрезания.
Каждая полученная порция добавляется в ByteArrayOutputStream. При результате
чтения <= 0 цикл заканчивается. Это учитывает особенность выданной библиотеки:
при оборванном соединении она может вернуть 0 вместо -1. Стандартный readAllBytes
в этом случае способен зациклиться. Размер блока не ограничивает размер всего тела.
BigInteger из CONTENT_LENGTH сравнивается с фактическим bytes.length.
Заявленная длина может быть испорчена при прямом обращении к FastCGI;
если размеры не совпали, возвращаем 400.
FastCGI отмечает конец тела отдельной записью; это не ожидание закрытия всего процесса Java.

`new String(bytes, UTF_8)` превращает байты в строку.
Длина числа не ограничена кодом, но чтение и вычисления используют оперативную память.
Бесконечный ввод физически обработать нельзя; это не ограничение в 64 или другое
заранее выбранное количество символов.

### parseForm(body)

Ожидаем ровно три пары, разделённые `&`.
`split("&", -1)` сохраняет пустую последнюю часть: лишний завершающий амперсанд
не будет незаметно проигнорирован.
`split("=", 2)` разделяет каждую пару только по первому знаку равенства.
Отсутствие `=` считается неправильным форматом.

URLDecoder превращает `%2E` в точку, `%2B` в плюс, а обычный `+` — в пробел:
так устроена кодировка application/x-www-form-urlencoded.
Поэтому JavaScript создаёт тело через URLSearchParams, а не вручную.
Повреждённая запись вроде `%GG` вызывает IllegalArgumentException.

Допустимы только имена x, y, r. `putIfAbsent` кладёт значение только при
отсутствии ключа. Если вернул не null, ключ уже был: повтор запрещён.
При ровно трёх уникальных разрешённых именах все нужные поля гарантированно присутствуют.
Порядок полей не важен. Лишние и повторные параметры отклоняются,
потому что иначе разные серверы могли бы выбрать первое или последнее значение.

### Проверка чисел

X и R проверяем как строки по Set: select должен передать ровно своё значение.
Это означает, например, что X = `1.0` и R = `1e0` отклоняются,
хотя математически могут обозначать разрешённое число.

Y нормализуем так же, как в браузере: убираем крайние обычные пробелы,
заменяем запятую на точку только для вычислений. Далее проверяем десятичный формат.
Только после этого создаём BigDecimal. Тем самым не допускаем NaN,
Infinity и экспоненты. Корректные длинные десятичные дроби проходят ту же проверку.

Сравнение с THREE.negate() и THREE проверяет строгий открытый интервал.
После валидации вызывается AreaChecker.contains.
Исходная запись хранится отдельно в originalY. В JSON возвращается именно она:
`+01,500` остаётся `+01,500`, `-0` остаётся `-0`, конечные нули сохраняются.
BigDecimal используется для вычислений, а не для переформатирования записи в таблице.

### Создание результата

Прошедшие наносекунды делим на 1000 и получаем микросекунды.
Измеряется чтение, разбор и вычисление до формирования JSON,
а не полное время от нажатия кнопки до ответа браузера.
`Instant.now()` даёт календарное время результата в UTC.
Длительность и календарное время берутся разными часами, потому что решают разные задачи.

JSON содержит строки координат, boolean hit, строку времени и целое elapsedMicros.
Строки координат сохраняют все введённые значащие десятичные цифры.
Если передать их JSON-числами, JavaScript мог бы сразу округлить их как Number.

В этой небольшой работе JSON собирается конкатенацией строк.
Это допустимо именно потому, что в него попадают только значения из списков,
проверенная десятичная запись числа, boolean, Instant и целое время.
Необработанный текст пользователя туда не вставляется.
Если добавлять произвольные комментарии пользователя, понадобится полноценное
экранирование JSON или библиотека сериализации.

### Обработка ошибок

IllegalArgumentException при разборе формы обрабатывается и превращается в 400.
`error(status, message)` создаёт JSON вида `{"error":"..."}`.
Все сообщения, передаваемые этой функции, постоянные и не содержат сырой ввод.
Метод возвращает Response; отправкой байтов занимается Main.

## 11. `src/Main.java`: серверный цикл FastCGI

После дополнительного задания обработка передана пулу потоков.
Подробный актуальный разбор каждого шага, Thread.sleep и особенностей
System.in/out находится в [ПАРАЛЛЕЛЬНОСТЬ.md](ПАРАЛЛЕЛЬНОСТЬ.md).

### main и настройка

`public static void main(String[] args)` — точка входа в Java-приложение.
Параметр запуска `-DFCGI_PORT=24001` создаёт системное свойство.
Это не переменная окружения и не аргумент после имени jar.
Библиотека читает его и открывает FastCGI-сокет.
В текущей версии Main сам создаёт серверный сокет и передаёт его библиотеке:
адрес 127.0.0.1 разрешает подключение только своему Apache. Переопределение
accept устанавливает таймаут 10 секунд сразу после подключения, ещё до разбора
FastCGI-заголовков. startupProps сохраняет системные свойства, acceptCalled и
isFCGI указывают библиотеке, что сокет уже подготовлен.
Без свойства программа выдаёт понятную ошибку запуска.

`PrintStream log = System.err` сохраняет исходный поток ошибок.
Это важно именно для приложенной библиотеки: она подменяет System.in,
System.out, System.err потоками текущего FastCGI-запроса.
Если нужно писать в обычный серверный журнал, используем сохранённый log.

### FCGIaccept

В бесконечном цикле `FCGIaccept()` ждёт запрос, обрабатывает FastCGI-метаданные
и подготавливает потоки. Нормальный результат — неотрицательное число.
Данные текущего запроса доступны через FCGIInterface.request.
Сам accept работает последовательно и вызывается главным потоком.
После приёма объект запроса отделяется от общей ссылки библиотеки и передаётся
работнику. Теперь один Java-процесс может обрабатывать четыре запроса одновременно.

Если accept вернул отрицательное значение, проверяем серверный сокет.
При невозможности открыть порт не делаем вид, что сервер работает: завершаемся с ошибкой.
Если ошибка относилась к отдельному подключению, закрываем его,
сбрасываем request и продолжаем принимать следующие подключения.
`continue` начинает следующую итерацию цикла.

### Обработка запроса

У принятого сокета ставим таймаут чтения 10 секунд.
Берём params и передаём их вместе с System.in в RequestHandler.handle.
Ожидаемые ошибки пользовательского ввода уже оформлены как Response с 4xx.
Неожиданное исключение ловится отдельно: в журнал пишется имя класса ошибки,
клиент получает 500 без деталей внутреннего устройства сервера.
Отдельный внешний catch защищает цикл от ошибки отправки в разорванное соединение.

Приложенная библиотека сама разбирает начало FastCGI до возврата FCGIaccept.
Наш таймаут применяется после этого этапа. Поэтому нельзя заявлять,
что сторонняя библиотека гарантированно выдерживает любые повреждённые
низкоуровневые FastCGI-пакеты или массовую нагрузку.
Обычные неверные HTTP-параметры покрыты проверками приложения.

### send(response): правильные заголовки и байты

Сначала переводим JSON в UTF-8-байты.
Content-Length должен равняться **числу байтов**, а не числу Java-символов.
Русская буква обычно занимает несколько байтов, поэтому String.length()
для длины HTTP-тела не подходит.

Заголовки:

| Заголовок | Назначение |
|---|---|
| `Status: 200 OK` или другой код | CGI-заголовок статуса для Apache |
| `Content-Type: application/json; charset=UTF-8` | Тип и кодировка ответа |
| `Content-Length` | Длина тела в байтах |
| `Cache-Control: no-store` | Не сохранять результат в HTTP-кэше |
| `X-Content-Type-Options: nosniff` | Не пытаться угадывать другой тип содержимого |
| `Allow: POST` при 405 | Разрешённый метод |

`\r\n` отделяет строки заголовков, пустая строка отделяет заголовки от тела.
Заголовки кодируются ASCII, JSON — UTF-8.
`System.out.writeBytes` пишет подготовленные байты без случайной перекодировки
через системную кодировку Windows или Helios.
`flush()` отправляет накопленное содержимое дальше.
Выражение `switch` выбирает английское описание статуса по его числовому коду,
чтобы заголовок Status содержал и код, и стандартную текстовую причину.
Окончательное завершение FastCGI-ответа выполняет библиотека при следующем accept.
Печатать отладочный текст в System.out нельзя: он станет частью ответа и испортит JSON.

## 12. HTTP: что именно идёт по сети

Упрощённый запрос браузера:

```http
POST /api/check HTTP/1.1
Host: localhost:8080
Content-Type: application/x-www-form-urlencoded;charset=UTF-8
Content-Length: 14

x=1&y=-1.5&r=2
```

Content-Length здесь 14 байт: тело содержит только ASCII.
Строка запроса содержит метод и путь, далее идут заголовки, пустая строка, тело.
GET обычно получает ресурс, параметры часто передаются в URL.
POST отправляет данные в теле. POST сам по себе не шифрует данные:
шифрование транспорта обеспечивает HTTPS или SSH-туннель.

Упрощённый ответ Java в формате CGI, до обработки Apache:

```text
Status: 200 OK
Content-Type: application/json; charset=UTF-8
Content-Length: ...

{"x":"1","y":"-1.5","r":"2","hit":true,"time":"...","elapsedMicros":15}
```

Apache преобразует Status в обычный HTTP-статус ответа браузеру.
Точка в JSON десятичная, true — boolean, строки заключены в двойные кавычки.
JSON — формат данных, не HTML и не исполняемый JavaScript.

### Статусы нашей работы

| Код | Когда появляется |
|---|---|
| 200 | Успешная проверка, и попадание, и промах |
| 400 | Некорректные поля, значения, длина или параметры в адресе |
| 405 | Неправильный метод, например GET вместо POST |
| 415 | Неподдерживаемый Content-Type |
| 500 | Неожиданный сбой обработки Java |
| 502 в локальном режиме | Локальная HTTP-прослойка не получила ответ Java |

Промах — нормальный результат, поэтому это 200, а не ошибка 400.
400 означает, что точку вообще нельзя корректно обработать по правилам ввода.
Apache может вернуть собственную HTML-ошибку ещё до Java;
клиентский код умеет сообщить и о таком ответе.

## 13. Apache: разбор `config/httpd.conf`

ServerRoot задаёт базу относительных путей Apache — `/usr/local` из шаблона.
Listen 24000 задаёт HTTP-порт. ServerName задаёт имя сервера.
PidFile хранит номер процесса, ErrorLog — ошибки, CustomLog — обращения.
Mutex указывает доступный пользователю каталог для служебных блокировок.
Эти каталоги нужно создать перед запуском, как указано в README.

LoadModule подключает модули Apache: авторизацию доступа, MIME-типы,
главную страницу каталога, алиасы, журнал, ограничение медленных запросов и FastCGI.
Пути взяты из выданного Helios-шаблона; на другом компьютере они могут отличаться.
Поэтому перед запуском выполняют `httpd -t`.

DocumentRoot указывает именно на public. Исходники Java и теория не являются
обычными статическими файлами сайта. DirectoryIndex выбирает index.html
при обращении к корню. TypesConfig и AddType задают MIME-типы файлов.
AddDefaultCharset задаёт UTF-8 по умолчанию.

В `<Directory />` весь доступ сначала запрещается.
Затем `<Directory ".../public">` разрешает только нужный каталог.
Options None запрещает дополнительные возможности вроде списка файлов,
AllowOverride None запрещает переопределять правила через .htaccess.

`LimitRequestBody 0` отключает ограничение размера тела на уровне Apache,
чтобы длинная дробь доходила до Java целиком.
RequestReadTimeout ограничивает медленную передачу заголовков и тела.
Timeout задаёт общий предел ожидания сетевых операций Apache.
ServerTokens и ServerSignature сокращают служебную информацию о сервере.

FastCgiIpcDir задаёт каталог служебных файлов модуля внутри нашего домашнего каталога.
FastCgiExternalServer связывает путь build/lab2.jar с уже запущенным Java-процессом
на 127.0.0.1:24001. Сам Apache **не запускает jar**: Java запускается отдельно.
Alias связывает URL `/api/check` с этим зарегистрированным FastCGI-приложением.
Directory для build разрешает модулю обратиться к приложению.

В оригинальном шаблоне был `-nph`. Здесь он убран, потому что Java возвращает
обычные CGI-заголовки с `Status`, а HTTP-ответ оформляет модуль.
NPH означал бы другой режим с самостоятельно подготовленным полным HTTP-ответом.
Не нужно возвращать строку `HTTP/1.1 200 OK` вместо CGI Status в этой конфигурации.

HTTP-порт и FastCGI-порт различаются. При смене FastCGI-порта нужно согласовать
запуск Java и FastCgiExternalServer. При смене расположения проекта — все абсолютные пути.
Здесь подготовлена конфигурация для логина s504568 из первой работы;
фактический запуск на Helios нужно проверить в своей SSH-сессии.

## 14. Сборка и локальные инструменты

Это вспомогательный код для запуска, а не отдельный фреймворк приложения.
На защите основное внимание обычно нужно уделить форме, AJAX, HTTP,
FastCGI-циклу, валидации и геометрии.

### tools/build.mjs

Расширение .mjs означает JavaScript-модуль Node.js.
`import` подключает встроенные модули fs, child_process, url, path.
В отличие от браузерного JavaScript, Node может читать файлы и запускать Java.
`ROOT` вычисляет абсолютный путь проекта от расположения скрипта,
поэтому сборка не зависит от текущего каталога терминала.

mkdirSync создаёт build/classes и build/lib вместе с недостающими родителями.
copyFileSync копирует FastCGI-библиотеку рядом с итоговым jar.
writeFileSync создаёт манифест с Main-Class и Class-Path.
Цикл запускает javac и jar через spawnSync. Аргументы передаются массивом,
поэтому пути с пробелами не требуют ручной сборки shell-команды.
Если команда не найдена или завершилась с ошибкой, сборка останавливается.

`javac --release 17` создаёт классы для Java 17.
`-encoding UTF-8` правильно читает русский текст исходников.
`-cp` указывает библиотеку для компиляции, `-d` — каталог .class-файлов.
`jar cfm` упаковывает классы с манифестом. Библиотека не включается внутрь
итогового jar, поэтому рядом должна оставаться папка build/lib.
Последняя проверка в build.mjs запускает build(), только если файл вызван
напрямую, а не импортирован как модуль другим скриптом.

### build.sh, start-fastcgi.sh, run.cmd

build.sh повторяет сборку средствами shell для Helios.
`set -eu` останавливает скрипт при ошибке или использовании неопределённой переменной.
`cd "$(dirname "$0")"` переходит в каталог самого скрипта.
mkdir -p создаёт недостающие каталоги, cp копирует библиотеку,
printf записывает манифест, javac и jar выполняют сборку.

start-fastcgi.sh переходит в папку проекта и запускает Java.
`${FCGI_PORT:-24001}` использует заданную переменную окружения FCGI_PORT
или порт 24001 по умолчанию. Самой Java значение передаётся уже через `-D`.
`exec` заменяет процесс скрипта процессом Java, упрощая остановку.

run.cmd — оболочка для двойного щелчка в Windows.
`cd /d "%~dp0"` переходит на нужный диск и в папку скрипта.
`node tools/run.mjs` запускает локальный режим.
При ошибке pause оставляет окно открытым, чтобы прочитать сообщение.

### tools/run.mjs

Сначала вызывает build. Затем кратковременно резервирует свободный порт
через net.createServer с портом 0: ОС сама выбирает свободное значение.
Резервирование закрывается, Java запускается на этом порту через spawn.
Небольшое окно гонки между освобождением порта и запуском Java теоретически остаётся;
при реальном конфликте Java завершится и ошибка будет видна.

createDevServer создаёт локальную HTTP-прослойку на 127.0.0.1:8080.
Обработчики сигналов SIGINT/SIGTERM останавливают Java и HTTP-сервер.
События error/exit не дают локальному режиму молча продолжать работу без Java.
Node не вычисляет принадлежность точки области.

### tools/dev-server.mjs: запись FastCGI

record создаёт 8-байтовый заголовок записи FastCGI и добавляет её содержимое.
Версия — 1, request id — 1. Разные запросы идут через отдельные соединения,
поэтому одинаковый id внутри этих разных соединений допустим.
writeUInt16BE пишет двухбайтовое число старшим байтом вперёд.
Функция records делит большое содержимое на записи по 65535 байт — это предел
размера одной записи FastCGI. Записей может быть несколько, поэтому это
не ограничивает длину всего числа или запроса.

Типы используемых записей: 1 — начало запроса, 4 — параметры,
5 — тело запроса, 6 — обычный вывод, 3 — завершение запроса.
Пустые записи параметров и тела отмечают конец соответствующего потока.
encodeLength кодирует длину имени/значения одним байтом для коротких строк
или четырьмя для более длинных — это правило протокола FastCGI.

### fastcgiRequest(params, body, port)

Создаёт Promise и TCP-соединение к Java. После connect собирает пары параметров
и записи BEGIN/PARAMS/STDIN, затем отправляет их через socket.write.
Таймаут и события error/end отклоняют Promise, если ответ получить не удалось.
`finished` не даёт считать штатное завершение обрывом.

Данные TCP могут прийти по частям: один data не равен одному сообщению.
Поэтому буфер pending накапливает байты, а цикл выделяет полные FastCGI-записи
по длине из заголовка и размеру padding.
STDOUT-записи накапливаются в output. При END_REQUEST соединение закрывается,
Promise возвращает полный CGI-ответ. Искусственного ограничения длины ответа нет,
иначе Java могла бы вернуть длинное число, а локальная прослойка — потерять его.
Это минимальный клиент для тестирования данного приложения, не универсальный
FastCGI-прокси со всеми возможностями протокола.

### createDevServer(fcgiPort)

Заранее перечисляет четыре допустимых статических URL: `/`, `/index.html`,
`/style.css`, `/script.js`. Пользовательский путь не подставляется напрямую
в путь файловой системы, поэтому запрос `/src/Main.java` не отдаёт исходник.
Для статики разрешены GET и HEAD; HEAD возвращает заголовки без тела.

Для `/api/check` читает всё тело без обрезания,
собирает CGI-параметры и вызывает fastcgiRequest.
Полученный ответ разделяет по пустой строке: заголовки отдельно, тело отдельно.
CGI Status превращается в HTTP-статус, остальные заголовки передаются браузеру.
При недоступной Java возвращает JSON с 502.
requestTimeout и headersTimeout ограничивают ожидание входящего HTTP-запроса.

## 15. Проверки: что доказывают и чего не доказывают

### tests/integration.mjs

Использует встроенный assert: при несовпадении ожидаемого и фактического
результата скрипт завершается ошибкой. Поднимает отдельную Java на свободном порту.
Функция call отправляет настоящий FastCGI-запрос, разбирает статус и JSON,
сверяет фактический размер ответа с Content-Length.
Функция point проверяет результат конкретной точки и поля времени.

Проверяется сетка всех X, всех R и дробных Y с шагом 0.25;
отдельные длинные дроби по разные стороны дуги и прямых;
неверные поля, типы, методы, длины, повторы и неизвестные параметры.
После плохих запросов отправляются хорошие, чтобы обнаружить остановку процесса.
Promise.all создаёт 20 одновременных подключений; Java обслуживает их пулом
из четырёх работников. Отдельный tests/parallel.mjs доказывает перекрытие sleep.
Дополнительно запускается локальная HTTP-прослойка и проверяется раздача файлов
и отправка формы через HTTP. finally останавливает тестовые процессы.

### tests/frontend.mjs

Запускает настоящий script.js в изолированной среде Node vm.
Вместо реального браузерного DOM, localStorage и fetch подставлены небольшие
управляемые объекты. Это позволяет воспроизвести запрет хранения, битый JSON,
ошибку сети и повторное нажатие без изменения пользовательского браузера.
Проверяется состояние кнопок после сбоя, сохранность истории и лимит записей.
Это не замена визуальной проверке в браузере: макет и Canvas проверяются отдельно.

Прохождение тестов подтверждает перечисленные сценарии. Оно не является
математическим доказательством отсутствия любых ошибок ОС, Apache или библиотеки.
Фактическое окружение Helios проверяется командой httpd -t и запросом curl.

## 16. Что сказать на защите

### «Где считается попадание?»

На сервере Java, в AreaChecker.contains. JavaScript только проверяет ввод,
отправляет запрос, хранит и показывает ответ. Рисунок не является источником истины.

### «Зачем проверять на сервере, если уже есть JavaScript?»

Пользователь может отключить JavaScript, изменить HTML или отправить запрос curl.
Браузерная проверка нужна для удобства, серверная — для корректности вычислений.

### «Где здесь AJAX?»

В обработчике submit: preventDefault отменяет обычную отправку страницы,
fetch делает POST, await получает JSON, затем обновляются таблица и canvas.
Документ полностью не перезагружается.

### «Почему данные не в адресной строке?»

По варианту требуется POST с данными в теле. Дополнительно сервер отклоняет
непустой QUERY_STRING, чтобы не смешивать два источника параметров.

### «Чем FastCGI отличается от HTTP?»

HTTP используется между браузером и Apache. FastCGI — между Apache и Java,
с отдельными двоичными записями для параметров, ввода и вывода.
Браузер с Java напрямую по FastCGI не общается.

### «Почему не double и не epsilon?»

Ввод — десятичные строки без заданного лимита цифр. BigDecimal проверяет их точно
в пределах ресурсов Java и компьютера.
При epsilon можно случайно включить точку, которая чуть-чуть за границей.
Здесь границы включаются не допуском, а точным сравнением <=.

### «Где история и сколько она живёт?»

В localStorage браузера: до очистки данных сайта или удаления нашим действием.
Она привязана к origin — схеме, хосту и порту.
На другом компьютере или адресе будет другая история.
Лимит — последние 500 записей; серверную базу или общие сессии эта работа не реализует.

### «Зачем textContent вместо innerHTML?»

Данные должны отображаться текстом. innerHTML интерпретировал бы их как разметку.
Вместе с проверкой структуры ответа textContent уменьшает возможность XSS.

### «Что произойдёт, если сервер выключить?»

Браузер покажет ошибку соединения, ответ локального прокси/Apache либо таймаут.
finally снова включит кнопку. Старая история сохранится, после восстановления
сервера можно повторить отправку.

### «Время обработки — это время сети?»

Нет. Длительность измерена System.nanoTime внутри Java до формирования JSON.
Календарное время берётся Instant.now. Ожидание сети и рисование страницы не включены.

### «Какие ограничения нужно честно назвать?»

Однопоточная сторонняя FastCGI-библиотека, ограниченная браузерная история,
возможная перезапись при одновременных записях вкладок, необходимость отдельно
проверить Apache на Helios. Любое приложение можно вывести из строя исчерпанием
ресурсов или ошибками окружения; здесь обработаны конкретные типичные проверки ввода и сети.

## 18. Готовый комплект для WinSCP

в `helios-upload`. В копии конфигурации пути заменяются на папку из скриншота:
`/home/studs/s504568/web/lab2/`. Основная конфигурация исходного проекта не меняется.
На сервер переносят содержимое комплекта, поэтому Node.js и компилятор там не нужны.

геометрия, AJAX и серверная валидация от них не зависят.

## 19. Публичный адрес se.ifmo.ru через public_html

Действующий адрес — `https://se.ifmo.ru/~s504568/lab2/`. Здесь не нужен
локальный SSH-туннель: общий веб-сервер открывает каталог `~/public_html/lab2`.
Это принцип из инструкции AppLoidx. Код публикации лежит в deploy/public_html.

В общем Apache доступен PHP, но не включён модуль HTTP-прокси. Поэтому
index.php выполняет только роль шлюза между публичным HTTPS-адресом и своим
Apache на 127.0.0.1:24000. Свой Apache отдаёт HTML/CSS/JS, а проверку точки
передаёт Java FastCGI. Геометрия, проверка чисел и формирование результата
по-прежнему находятся в Java. PHP не считает попадание и не округляет числа.

В .htaccess DirectoryIndex выбирает index.php. RewriteEngine включает
переписывание URL, RewriteRule отправляет запросы к index.php. Флаг END
останавливает переписывание, чтобы запрос не зациклился. Исходный REQUEST_URI
позволяет шлюзу определить, просили главную страницу, файл или api/check.

В index.php сначала задаются no-store и nosniff. gatewayError устанавливает
HTTP-статус и возвращает JSON с фиксированным сообщением через json_encode.
Затем проверяется префикс URL и выбирается маршрут из фиксированного массива.
Допустимы только пять видов ресурсов: главная страница, index.html, style.css,
script.js и api/check. Неизвестные адреса дают 404. Пользователь не может
указать другой сервер или путь к исходникам: внутренний адрес жёстко задан.

Метод проверяется по списку GET/HEAD/POST. Тело читается из php://input,
Content-Type и строка запроса передаются дальше. stream_context_create задаёт
параметры внутреннего HTTP-запроса; file_get_contents выполняет его.
ignore_errors позволяет прочитать также тело ответа с HTTP 400/405/415;
follow_location = 0 запрещает автоматически следовать перенаправлениям.
Таймаут — 10 секунд. Символ @ подавляет техническое предупреждение PHP при
обрыве соединения: вместо него пользователь получает наше JSON-сообщение.

Массив http_response_header содержит заголовки ответа собственного Apache.
Регулярное выражение извлекает числовой статус. Content-Type и Allow
передаются браузеру. Для API ответ без application/json заменяется на
503 с нашим сообщением: так HTML-ошибка Apache при остановленной Java не
попадает в таблицу. Для обычного успешного ответа возвращаются исходные байты.
Ни число цифр Y, ни конечные нули шлюзом не обрезаются.

deploy/publish.sh создаёт ~/public_html/lab2, устанавливает права 755 у
публичных каталогов и 644 у файлов, копирует index.php и .htaccess.
Он вызывается командой запуска server.sh. Основные исходники и jar остаются
в ~/web/lab2, в общедоступный каталог они не копируются.

Проверка публичной цепочки: `node tests/publication.mjs`. Она сравнивает
отданные HTML/CSS/JS с локальными файлами, проверяет POST и неверные запросы,
закрытые маршруты, HTTP-статусы и точное сохранение дроби более 300000 символов.
На реальном Helios также проверены остановка Java, сообщение об ошибке на странице
и успешная повторная отправка после восстановления.
