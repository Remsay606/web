## Быстрый запуск на Windows

Требуются **JDK 17 или новее** (`java`, `javac`, `jar` в PATH) и **Node.js 18 или новее**.
На компьютере, где подготовлена работа, JDK и Node.js уже доступны.

Откройте `run.cmd` или выполните из папки `lab2`:

```powershell
node tools/run.mjs
```

Откройте <http://localhost:8080>. Остановка — **Ctrl+C** в окне запуска.
Скрипт сам собирает Java, запускает её и локальный HTTP-сервер.
Локальная HTTP-страница доступна только с этого компьютера. Открытие `public/index.html`
двойным щелчком не запускает Java и не подходит для отправки запросов.

Если порт 8080 занят, остановите прежний экземпляр приложения. При ошибке
сборки проверьте `java -version`, `javac -version`, `node --version`.

Локальный Node-сервер нужен для удобной проверки без установки Apache на Windows.
Он действительно переводит запросы в **FastCGI**; геометрию всегда считает Java.
На Helios по заданию используется **Apache**, Node.js там не нужен.

## Точный вариант и поведение

| Параметр | Требование |
|---|---|
| X | Select: −3, −2, −1, 0, 1, 2, 3, 4, 5 |
| Y | Text: строго −3 < Y < 3 |
| R | Select: 1, 1.5, 2, 2.5, 3 |
| Метод | POST, `application/x-www-form-urlencoded` |
| Ответ | JSON: x, y, r, hit, time, elapsedMicros |

Область — объединение трёх фигур, их границы включены:

1. Четверть круга: `x >= 0`, `y >= 0`, `x² + y² <= R²`.
2. Треугольник: `x <= 0`, `y >= 0`, `y - x <= R/2`.
3. Прямоугольник: `0 <= x <= R/2`, `-R <= y <= 0`.

Знак минус при вводе — обычный `-`. Для Y принимаются точка и запятая,
знак `+`, `.5`, `1.`, пробелы по краям. Экспоненциальная запись (`1e0`),
бесконечность, NaN, шестнадцатеричная запись, текст и управляющие символы отклоняются.
Искусственного ограничения количества цифр в Y нет. Значение проверяется точно,
без округления; в ответе, таблице и истории сохраняется исходная запись числа
(включая запятую/точку и конечные нули), удаляются только крайние обычные пробелы.
Например, `2,109000` сохраняется как `2,109000`. Число `3,109` отклоняется
из-за диапазона Y, а не длины. Предел фактически определяется ресурсами Java,
браузера и компьютера. При заполнении localStorage появляется предупреждение;
результат остаётся доступен на текущей странице без обрезания числа.
X и R на сервере должны точно совпадать со значениями списка.

История хранится в **localStorage этого браузера и этого адреса сайта**,
сохраняется между запросами и после перезагрузки. Это не общая серверная база:
другой браузер, порт или адрес имеют отдельную историю. Сохраняются последние
500 проверок; при превышении лимита удаляются самые старые. Очистка истории
затрагивает только ключ этой работы. При запрете localStorage проверки продолжаются,
а пользователь видит сообщение о невозможности постоянного сохранения.
Одновременная запись из нескольких вкладок подчиняется правилу «последняя запись побеждает».

График показывает все точки с выбранным R и автоматически подбирает масштаб,
чтобы область и самая далёкая точка помещались на холсте с запасом. Клик по графику
не отправляет координаты: по варианту X выбирается из списка.

`time` — серверное время в UTC; браузер показывает его в своём часовом поясе.
`elapsedMicros` — время обработки в Java до формирования JSON, в микросекундах,
измеренное монотонными часами. Сеть и время отрисовки туда не входят.

## Развёртывание на Helios

Основной действующий вариант — [ГЕЛИОС.md](ГЕЛИОС.md): публикация через public_html,
Apache 24000 и Java 35481 в `~/web/lab2`. Он проверен 17.11.2026.
Ниже описана альтернативная ручная установка в `~/lab2`:
эти команды выполняются **после входа в свой аккаунт Helios**.
Порты 24000 и 24001 — значения исходного шаблона;
при занятости выберите свободную пару и замените их согласованно.

### 1. Разместить папку

Скопируйте **содержимое `lab2` в `~/lab2`** на Helios, сохранив структуру.
Можно использовать SFTP-клиент. Пример из PowerShell в локальной папке `web`:

```powershell
scp -P 2222 -r lab2 s504568@helios.cs.ifmo.ru:~/
```

Если ваша схема доступа использует другой SSH-адрес или порт, используйте
обычные для вашего аккаунта настройки. Пароли и ключи в проект не включены.

### 2. Собрать и проверить конфигурацию

```sh
cd ~/lab2
java -version
javac -version
sh build.sh
mkdir -p httpd-root/mutex-dir httpd-root/fastcgi
/usr/local/sbin/httpd -t -f "$HOME/lab2/config/httpd.conf"
```

Нужна Java 17+. Если системная Java старее, подключите установленный JDK 17+
через PATH. Если папка размещена не в `~/lab2` или логин отличается от `s504568`,
исправьте абсолютные пути в `config/httpd.conf` до запуска.
Пути к модулям `/usr/local/libexec/apache24/` взяты из приложенного шаблона;
если окружение Helios изменилось, проверка `httpd -t` покажет конкретную ошибку.

### 3. Запустить два процесса

Первое SSH-окно:

```sh
cd ~/lab2
sh start-fastcgi.sh
```

Второе SSH-окно:

```sh
/usr/local/sbin/httpd -f "$HOME/lab2/config/httpd.conf" -k start
```

Java работает в первом окне; остановка — Ctrl+C. Apache запускается от
пользователя, `sudo` не требуется. Для работы после закрытия SSH используйте
свой обычный терминальный мультиплексор, например tmux, если он установлен.

При необходимости другого FastCGI-порта:

```sh
FCGI_PORT=24003 sh start-fastcgi.sh
```

Тогда замените `24001` в `FastCgiExternalServer` на `24003`.
При смене HTTP-порта измените `Listen` и `ServerName`.

### 4. Проверить HTTP и остановить Apache

На Helios:

```sh
curl -i http://127.0.0.1:24000/
curl -i -d 'x=1&y=-1.5&r=2' http://127.0.0.1:24000/api/check
curl -i -d 'x=1&y=3&r=2' http://127.0.0.1:24000/api/check
```

Вторая команда должна вернуть HTTP 200 и `"hit":true`, третья — HTTP 400.
Для открытия страницы с Windows можно сделать SSH-туннель:

```powershell
ssh -p 2222 -L 8081:127.0.0.1:24000 s504568@helios.cs.ifmo.ru
```

Оставьте окно открытым, перейдите на <http://localhost:8081>.
Это также позволяет показать именно Apache с Helios, даже если внешний порт закрыт.

Остановка Apache:

```sh
/usr/local/sbin/httpd -f "$HOME/lab2/config/httpd.conf" -k stop
```

При HTTP 500/502/503 проверьте, работает ли Java, совпадают ли порты и что
записано в `~/lab2/httpd-root/error.log`. FastCGI-порт не является HTTP-портом:
его нельзя проверять обычным `curl http://localhost:24001`.

## Автоматические проверки

В папке `lab2` (перед пересборкой остановите запущенный локальный сервер через Ctrl+C;
Windows блокирует перезапись используемого jar):

```powershell
node tests/integration.mjs
node tests/frontend.mjs
```

Первый скрипт собирает Java, поднимает отдельный процесс на свободном порту,
выполняет проверки и останавливает его. Проверяются геометрия на сетке,
границы с высокой точностью, все X и R, повреждённые параметры, неправильные
метод и тип тела, совпадение длины тела с CONTENT_LENGTH, продолжение работы после ошибок,
дроби до 300000 цифр после разделителя, сохранение всех цифр, нулей и запятой,
20 параллельных подключений и локальная HTTP-прослойка.
Второй скрипт проверяет реальный JavaScript страницы
с изолированными DOM/storage/fetch: неверный ввод, повреждённая история,
лимит записей, запрет storage, успешный AJAX, сетевые ошибки и двойное нажатие,
отправку, отображение и загрузку истории с дробью длиной более 300000 символов.
Внешние зависимости и доступ к пользовательской истории браузера не нужны.

Ручная проверка перед защитой: пустые поля; Y = ±3; Y = `2.999999999999999999`;
запятая; попадание и промах; смена R; перезагрузка; отключение Java и повторный
запрос; восстановление Java; очистка истории; отправка неправильного запроса curl.

## Пределы устойчивости

Проверки сделаны и в браузере, и независимо в Java; вычисления используют
BigDecimal, вывод таблицы — textContent. Неверные запросы не должны прекращать
обработку последующих. Программного лимита длины числа или размера тела нет;
ожидание ответа страницы ограничено 12 секундами, история — 500 записями.
В Apache установлен `LimitRequestBody 0`, локальная прослойка разбивает большие
тела на несколько записей FastCGI и не обрезает ответ. Это учебное приложение
с последовательным приёмом FastCGI и ограниченным пулом работников: оно не обещает защиту от DDoS,
неисправностей ОС, исчерпания ресурсов или всех ошибок самой библиотеки.
Для работы на Helios требуется отдельно проверить реальное окружение Apache.
